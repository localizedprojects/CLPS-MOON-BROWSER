# CLAUDE.md: Lunar Horizon (lunar south-pole site and date planner)

This is a NASA Space Apps entry: a Flutter app (web + Android) for comparing south-pole landing sites and dates by Sun and Earth visibility above the local horizon (power and direct-to-Earth comms). See `PLAN.md` for the architecture and milestones.

## Source of truth
- **GitHub is the source of truth:** https://github.com/localizedprojects/CLPS-MOON-BROWSER (public, MIT).
  The web app is published from `main` to https://localizedprojects.github.io/CLPS-MOON-BROWSER/ by
  `.github/workflows/deploy-pages.yml`.
- **Work in a clone of this repository** (on Windows keep it on a short path outside synced folders,
  for example `C:\src\CLPS-MOON-BROWSER`). If it is missing:
  `git clone https://github.com/localizedprojects/CLPS-MOON-BROWSER`.
- **Branches and PRs:** start a branch for non-trivial work, push it, and open a PR into `main`; CI
  (`.github/workflows/ci.yml`) must pass before merging. Never force-push `main`.
- **Not in git:** `.venv`, `charts/node_modules`, `app/build`, and the SPICE kernels and LOLA DEMs in
  `$LUNAR_SP_CACHE` (default `~/.cache/lunar-sp`). Recreate them in the clone (see Commands).
  `app/assets/data/` and `app/assets/charts/` **are** committed.

## Layout
- `pipeline/`: Python precompute (spiceypy, numpy). The package is `pipeline/lunarsp/` and its tests are in `pipeline/tests/`.
- `pipeline/validation/`: cached JPL Horizons responses (commit these).
- `app/`: Flutter project.
  - `app/lib/core/`: pure Dart science and metrics with no Flutter imports, unit-tested.
  - `app/lib/state/`: app state (ChangeNotifier, provider).
  - `app/lib/widgets/`: UI (map = CustomPainter). **Graphs are React** (see `charts/`), embedded through `app/lib/widgets/chart_view*.dart`.
- `charts/`: React + Vite + TypeScript + Plotly chart bundle (sky plot, timeline, comparison). `npm run build` writes to `app/assets/charts/`, which is committed. The charts are render-only: they receive JSON from Flutter and post events back. Never put science in this bundle.
- `app/assets/data/`: generated compact data. **Commit it.** Regenerate it with the pipeline. Never hand-edit it.
- `app/test/fixtures/`: SPICE truth vectors generated by `python -m lunarsp.build fixtures`.
- Raw downloads go to `$LUNAR_SP_CACHE` (default `~/.cache/lunar-sp`). Never put them in the repo.

## Commands
On Windows, the venv Python is `.venv\Scripts\python.exe`. Run pipeline commands from `pipeline/`.
- Python env: `python -m venv .venv && .venv/Scripts/pip install -r pipeline/requirements.txt`
- Fetch data (about 570 MB, 605 MB with DE442): `python -m lunarsp.fetch` (add `extra` for DE442)
- Precompute everything: `python -m lunarsp.build all`. Sub-steps: `ephem`, `sites`, `validate`, `fixtures`. The map layers are a separate module: `python -m lunarsp.basemap` (`python -m lunarsp.basemap dem` rebuilds only the 400 m DEM and its `map.json` entry; then `python -m lunarsp.fixtures coarse` refreshes the coarse-horizon fixture).
- Refresh the Horizons cache (needs network): `python -m lunarsp.horizons --refresh`
- Python tests: `python -m pytest` (from `pipeline/`). Runs offline from the cache; tests needing kernels or DEMs skip if those are absent.
- Flutter (from `app/`):
  - `flutter pub get`
  - `flutter test`
  - `flutter analyze`
  - `flutter run -d chrome`
  - `flutter build web --release --base-href /<repo>/`
- Charts (from `charts/`): `npm install`, `npm run dev` (standalone with sample payload), `npm test` (vitest), `npm run build` (writes `../app/assets/charts/`)
- Blender renders (Blender 5.1 via `$BLENDER` or the default install path, CPU Cycles): `python -m lunarsp.build renders` runs render_prep → `blender -b -P pipeline/blender/render_site.py` / `render_overview.py` → render_post. This is slow (about 5 min per site at 4096×683, ±30° band, 32 samples); outputs go to `app/assets/data/renders/`. **The app no longer shows these renders** (user decision 2026-10-10); they are kept only as an independent skyline cross-check in `validation.json`. Visuals in the app come from the computed light & shadow map (`app/lib/core/shadow.dart`). The visualization aids (camera-invisible fill light, unlit near-field fan) must stay labeled. Renders must use real data only: LOLA terrain, SPICE Sun/Earth, physical lights. Never add cosmetic textures or fake stars.
- Emulator:
  - Start it: `flutter emulators --launch <your_avd>`
  - Run on it: `flutter run -d emulator-5554`
  - Screenshot: `adb exec-out screencap -p > shot.png` (adb is at `%LOCALAPPDATA%\Android\Sdk\platform-tools`)

## Science conventions (do not change silently)
- Body frame: `MOON_ME` (= `MOON_ME_DE440_ME421`). Latitudes are **planetocentric**. Longitudes are **east-positive**, normalized to [-180, 180).
- Ephemeris: DE440 (`de440s.bsp`) with `moon_pa_de440_200625.bpc` and `moon_de440_250416.tf`. DE442 is used only for cross-checks.
- Directions are apparent, using `LT+S`, matching JPL Horizons' "airless apparent AZ/EL". **No refraction.**
- Times are UTC via `naif0012.tls`. The app works in UTC `DateTime` / Unix ms.
- Reference sphere R = 1737.4 km. LOLA height = DN × 0.5 m. The default observer height is 2 m above terrain.
- Local ENU uses the spherical normal. Azimuth is clockwise from north, where north means increasing latitude, i.e. away from the pole. At lat −90°, north is the site's meridian.
- Sun angular radius = asin(695700 / r). Earth angular radius = asin(6378.1366 / r). The visible fraction uses 16-strip integration against the horizon mask.
- Sun criteria: `center` | `upperLimb` (any part; the default) | `fullDisk`. The power proxy is 1361 W/m² × (1 au / r)² × visibleFraction.
- Lunar eclipses (deliberate, documented change of 2026-10-29; `formula.md` §6.5): the Sun's visible fraction also excludes the part of its disk behind Earth's disk (both apparent `LT+S`, planar two-circle overlap), removed per strip inside the 16-strip integration. `center` also needs the Sun's centre outside Earth's disk and `fullDisk` needs no overlap; `SiteSeries.sunEclipse` keeps the covered share. Earth and DSN visibility are unaffected. The pipeline's 18.6-year averages do not include it yet.
- DSN-in-view: Moon center elevation ≥ 10° at Goldstone, Madrid, or Canberra, with Earth orientation from ITRF93 (`earth_1962_*_combined.bpc`). Do not use IAU_EARTH, which is off by about 0.1°.
- LOLA polar stereographic projection: lon 0 points up, 90°E points right. For a unit vector u, x = 2R·uy/(1−uz) and y = 2R·ux/(1−uz). This is verified against Shackleton and Mons Mouton.

## Conventions
- The Dart core is pure (no `package:flutter` imports in `lib/core`). Every core function gets a test in `app/test/core/`.
- Chart bridge protocol: Flutter→JS `window.phRender({type, ...})`; JS→Flutter `PH.postMessage(JSON)` (Android JavaScriptChannel) or `parent.postMessage` (web iframe). The message schema is in `charts/src/bridge.ts` and `app/lib/widgets/chart_bridge.dart`; keep the two in sync.
- Design system lives in `app/lib/theme.dart`, mirrored in `charts/src/theme.ts` and `charts/src/styles.css`: a deep-navy "instrument panel" (bg `#060B16`, panel `#0C1528`, raised `#12203A`, hairlines `#1E3050`), IBM Plex Sans for text and **IBM Plex Mono with tabular figures for every number** (fonts are bundled, OFL), uppercase `MicroLabel` section labels, small radii, and visible 2 px `ice` focus rings. Color carries meaning only: Sun = amber `#FFB000`, Earth = blue `#3D8BFD`, both = teal `#2EC4B6`. UI selection is neutral navy, never amber. Color is never the only encoding; also use shapes, patterns, and direct labels.
- Any approximation is labeled in the UI with the `FidelityBadge` widget. No placeholder data may be presented as real.
- Give every interactive widget a `Semantics` label. Tap targets must be ≥ 48 dp.
- Commit after each milestone with a message like `M<n>: ...`.
